# 系统设计说明

> 项目：基于服务器端通用模型的可访问式深度学习预测服务设计（2025JCCX099）
> 本文按项目简介逐项说明实现方式，可以作为结题报告"项目实施情况"和"创新与特色"部分的素材。

## 1. 总体架构

```
 外部终端（Python 脚本 / MATLAB / Excel / 仪器上位机 / 其他电脑浏览器）
        │  REST API（X-API-Key）              │  网页（JWT 登录）
        ▼                                     ▼
 ┌──────────────────────── 访问控制层 ────────────────────────┐
 │ 身份认证（JWT / API Key）→ 令牌桶限流（429）→ 权限校验          │
 │ （本人 / 团队共享 / 公开 / 仅已发布模型可被 API Key 调用）        │
 └───────────────────────────────────────────────────────────┘
        │                                     │
        ▼                                     ▼
 ┌──── 预测服务 ────┐                   ┌──── 训练服务 ────┐
 │ 并发闸门（503）    │                   │ 任务队列（线程池）  │
 │ 模型 LRU 缓存      │                   │ 每用户任务数上限    │
 │ 单条 / 批量 / 文件  │                   │ 进度与日志、可取消  │
 └────────┬─────────┘                   └────────┬─────────┘
          └──────────────┬───────────────────────┘
                         ▼
 ┌──────────────────── 预测流水线 ────────────────────────────┐
 │ SMILES 特征化 → 自动字段识别 → 缺失填充/编码 → 自动归一化       │
 │                         ↓                                    │
 │                模型适配器（统一接口）                           │
 │  通用基础模型 TabPFN │ 深度模型 FT-Transformer / ResMLP │       │
 │  轻量模型 GBDT / RF / 线性 / SVM / KNN / XGB / LGBM │ 外部 ONNX │
 │                         ↓                                    │
 │      评估指标 · 全局置换重要性 · 单样本遮挡解释                  │
 └───────────────────────────────────────────────────────────┘
          │ GPU 并发锁（RTX 5060 Ti 8GB）
          ▼
 存储：SQLite（用户、数据集、模型登记、任务、调用日志）+ 模型文件（joblib）
```

技术栈：Python 3.11、FastAPI、scikit-learn、PyTorch（CUDA 12.8）、TabPFN、SQLite；前端用 Vue 3、Element Plus、ECharts。

## 3. 关键设计

### 3.1 通用模型

TabPFN 是在大量合成表格数据上预训练的 Transformer 基础模型。预测时，它把训练样本作为上下文输入，不需要针对具体任务做梯度训练。化工、环境类实验数据通常只有几十到几千条，这种情况下 TabPFN 不用调参就能得到很好的效果，因此作为平台的"通用模型"，供不同学科的小样本预测任务共用。

### 3.2 自动归一化规则

- 如果超过 1/3 的数值列存在明显离群值（按 IQR 规则，离群点占比 > 5%），选择 **RobustScaler**
- 如果所有数值列都有固定上下界且分布较均匀，选择 **MinMaxScaler**
- 其他情况选择 **StandardScaler**

选择结果和依据会写进模型的"归一化报告"，用户也可以手动指定。

### 3.3 并发访问控制

| 层级 | 机制 | 超限时的结果 |
|---|---|---|
| 请求频率 | 令牌桶，每个用户 / API Key 有独立限额，允许短时突发 | 429 + Retry-After |
| 预测执行 | 全局信号量限制同时执行的预测数，超出的请求排队 | 排队超时返回 503 |
| 训练任务 | 线程池 + 每用户任务数上限 + 全局队列上限 | 429，提示排队已满 |
| GPU 资源 | GPU 信号量，限制同时占用显存的任务数 | 排队等待 |
| 模型加载 | LRU 缓存，同一模型只加载一次（双重检查锁） | — |

### 3.4 可解释性

- **全局**：置换重要性。在测试集上把某个原始特征打乱，看主指标下降多少。计算在原始特征层面进行，所以 One-Hot 编码后的类别特征、SMILES 展开出来的描述符，都会归并回用户能看懂的原始列名。
- **局部**：特征遮挡法。对一条样本，依次把某个特征替换为训练集的典型值（数值列用中位数，类别列用众数），预测值的变化量就是这个特征对本次预测的贡献。

## 4. 主要接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/v1/auth/login | 登录 |
| GET | /api/v1/templates | 数据模板 |
| POST | /api/v1/datasets | 上传数据集 |
| POST | /api/v1/jobs/train | 提交训练任务 |
| POST | /api/v1/quick/predict | 一键预测（上传 + 自动训练） |
| GET | /api/v1/models/{id}/schema | 查询模型输入字段 |
| POST | /api/v1/models/{id}/predict | JSON 预测（可带解释） |
| POST | /api/v1/models/{id}/predict-file | 文件批量预测 |
| POST | /api/v1/models/import | 接入外部模型 |
| GET | /api/v1/stats/system | 服务器实时状态 |

完整接口说明见 `http://服务器:8000/docs`。
